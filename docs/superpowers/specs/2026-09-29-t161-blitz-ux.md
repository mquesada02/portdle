# Ticket spec: Blitz end card nav tap and Leaderboards picker start (#161)

Tracker: https://github.com/mquesada02/portdle/issues/161. Parent: Spec 4 (#127, `docs/superpowers/specs/2026-09-28-spec4-backend.md`); map #114. Owner feedback from the live eye check, 2026-09-30. UI only: no migration, no owner steps.

## Problem Statement

Two things on the Blitz screen cost the player extra taps. On the end card, tapping Blitz in the nav does nothing, because the player is already on the Blitz route; only "Play again" leaves the end card. And the Leaderboards tab always opens on Mixed / Default / Sprint, so a player who just played Protocols / Inverted / Marathon must re-pick all three choices to see where the score stands. The picker also forgets every pick when the player switches to the Play tab and back.

## Solution

1. A tap on Blitz in the nav while the end card shows returns to the Arena, exactly as "Play again" does, phase motion included. A tap during a run in progress changes nothing. On the Blitz screen at rest, on either tab (the Arena is the Play tab), a tap changes nothing. "Play again" keeps its label and behavior.
2. The Leaderboards picker starts on the last run's Daily category, Orientation, and Blitz mode, with the window on All-time. With no stored run it starts on Mixed / Default / Sprint. A choice the player makes stays while the Blitz screen stays mounted, including across Play / Leaderboards tab changes. When a run ends, the picker resets to that run's Daily category, Orientation, and Blitz mode, and the window is untouched (owner decision 2026-09-30, answering a question raised while writing this spec); a manual pick is kept only until the next run ends.

## User Stories

1. As a player on the end card, I want a nav tap on Blitz to return me to the Arena, so that I can leave the end card without hunting for "Play again".
2. As a player on the end card, I want the nav tap to look the same as "Play again" (phase motion), so that the two exits feel the same.
3. As a player on the end card, I want "Play again" to keep working as it does now, so that nothing I know changes.
4. As a player in the middle of a run, I want a nav tap on Blitz to do nothing, so that a stray tap never ends or resets my run.
5. As a player on the Blitz screen at rest, I want a nav tap on Blitz to do nothing new, so that I stay on the tab I am on.
6. As a player who opens the Leaderboards tab, I want the picker to start on my last run's Daily category, Orientation, and Blitz mode, so that I see where my score stands at once.
7. As a player who has never played a run, I want the picker to start on Mixed / Default / Sprint, so that the picker still has a sensible start.
8. As a player, I want the window to start on All-time when the Blitz screen mounts, so that the start matches today.
9. As a player who picks another Leaderboard, I want my pick kept when I switch to the Play tab and back, so that I do not re-pick it.
10. As a player who finishes a run, I want the picker to reset to that run's Daily category, Orientation, and Blitz mode the next time I open Leaderboards, so that I see the Leaderboard I just played.
11. As a player who picked a window before a run, I want the window untouched when the run ends, so that my window choice stays.
12. As a player on a build with no `Remote`, I want the nav tap to leave the end card as well, and no picker or Leaderboards tab to appear, so that nothing points at a missing service.

## Implementation Decisions

- **Nav tap signal.** The router already records each navigation, even to the URL already showing, as a new history entry with a new key (`__TSR_key`) in its location state (a probe against a memory history showed two taps on Blitz on `/blitz` giving two new keys). The Blitz screen reads that key with the router's location hook. It keeps the last key it saw in a ref that starts at the key current at mount, and updates it on every change. When the key changes and the run has ended at that moment, the screen runs the same function "Play again" runs, so the motion is identical. When the run is in progress, or at rest, the change only updates the ref, so a tap made during a run never leaves the end card later when that run ends. The signal does not depend on `Remote`. No change to the nav or the shell.
- **Router transition.** The router already starts its own `switcher` view transition for any navigation inside one screen, so a nav tap on Blitz starts that transition today, at rest and mid-run as well. This ticket leaves that alone. On the end card, the `phase` transition from the return to the Arena follows it as a separate transition, not nested. Tests therefore assert on the `phase` type only.
- **Author call:** a browser Back or Forward between two `/blitz` entries also changes the key, so it also leaves the end card. The ticket names only the nav tap; this is accepted because it is the same kind of navigation to Blitz and needs no extra code to exclude.
- **Picker state moves up.** The Leaderboards component stops owning the window, Daily category, Orientation, and Blitz mode. The Blitz screen owns them and passes them down with their setters, so they survive the tab change, which unmounts the Leaderboards component. The window starts All-time.
- **Seed.** At mount, the picker's Daily category, Orientation, and Blitz mode come from the newest stored run, else Mixed / Default / Sprint (the same lookup the Setup dialog already does once at mount; the picker keeps its own state, separate from the dialog's, so a Cancel in the dialog never moves the picker). When a run ends, the screen sets the three to that run's values. Window is never reset.
- **Reseed moment.** A run ends in two places (the timeout expiry and a committed answer that spends the last life). The reseed therefore runs in the existing effect that reacts once to a run's end, not inside a state updater, and uses the ended run's own category, orientation, and mode from the run state, not from storage, so a failed storage write cannot change it. The end card shows and the tabs are hidden at that point, so the player cannot reach the Leaderboards tab before it runs.
- Leaderboards' own fetch effect, loading, error, empty, and pinned-row behavior do not change. The sync push on first open stays once per mount of the component, as now.
- No new glossary terms. `CONTEXT.md` is unchanged.

## Testing Decisions

- A good test renders `App` with `memoryStore` and (for the picker) the fake `Remote`, acts as the player, and asserts what the screen shows (the end card or the Arena, the selected pills, the Leaderboard read the fake received), never internal state.
- **Nav tap** (App-level, beside the Blitz Arena tests): finish a run to the end card, click the Blitz nav link (the test asserts only the visible outcome: the Arena replaces the end card after a tap, and a second tap after a new run ends does it again; the key change is an implementation detail), see the Arena ("New run" button) and no end card; the same with a run in progress: click the Blitz nav link and the HUD still reads the same round and score; a view transition with the `phase` type starting is asserted with `stubViewTransitions`, as the existing "Play again starts a view transition with the phase type" test does; at rest and mid-run the nav tap starts no `phase` transition (the router's own `switcher` transition may appear and is not asserted), and with the Leaderboards tab selected the tab stays; a tap during a run, followed by the run ending, leaves the end card showing; with no `Remote`, a nav tap on the end card returns to the Arena, and neither the Play / Leaderboards tabs nor a picker show. Back and Forward between two `/blitz` entries are deliberately untested.
- **Picker start** (App-level, beside the Leaderboards tests): with a stored run of Protocols / Inverted / Marathon, open Leaderboards and see those pills checked and All-time checked, and the Leaderboard read the fake `Remote` received is for that key; with no stored run see Mixed / Default / Sprint; pick another Leaderboard, switch to Play and back, see the pick kept; pick a window and another Leaderboard, finish a run of a different setup, open Leaderboards, see the run's Leaderboard and the picked window. Changing the Setup dialog's pills and cancelling leaves the picker's seed unchanged. The reseed is covered for a run ended by timeout (fake timers) and for a run ended by out of lives.
- Prior art: `blitz-arena.test.tsx` (Play again, view transition assertions) and `leaderboards.test.tsx` (fake `Remote`, tab and picker assertions).
- Gates: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` pass.

## Out of Scope

- Changing the label or behavior of "Play again".
- Remembering the picker across a page reload or in local storage.
- Any change to the Daily, History, or Codex nav behavior.
- Any backend, migration, or sync change.

## Further Notes

- Author call for the owner: Back or Forward between two `/blitz` history entries also leaves the end card (see Implementation Decisions).
- Terms follow `CONTEXT.md`: Leaderboard, Leaderboard window, Orientation, Blitz mode, Daily category, Arena, Run.
