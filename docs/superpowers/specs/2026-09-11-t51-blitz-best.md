# Spec: Blitz end card Best fix

Spec for #51. Tracker: https://github.com/mquesada02/portdle/issues/51

## Problem Statement

A player finishing their first-ever Blitz run sees the end card read "Best —" even though a Best was just stored for that run. The card's dash makes it look like nothing was saved, when in fact the write happened; the number simply never appears because of how the card computes what to show. A related smaller problem: "New best" never appears on a first run, even when the player scored above zero and there was no previous best to beat.

## Solution

The end card always shows a number for Best: the higher of the stored best and the score just earned, worked out fresh every time the card renders rather than depending on a background save having already finished. "New best" is shown when the run's score beats the previously stored best, or when there was no previously stored best and the score is above zero.

## User Stories

### End card

1. As a player finishing my first-ever Blitz run, I want the end card to read `Best n` with my score, so that the card never shows a dash.
2. As a player, I want `Best n` to be the higher of my stored best and this run's score, so that the number is always right no matter how the save is timed.
3. As a player, I want "New best" when this run beats my stored best, or when it is my first run with a score above zero, so that a first success is celebrated.
4. As a player whose second run scores lower than my first, I want the end card to keep showing my higher, earlier best and no "New best" badge, so that a worse run never looks like it improved my best.
5. As a player whose first-ever run scores zero, I want the end card to read `Best 0` with no "New best" badge, so that a zero score is not mistaken for an achievement.

### Maintainer

6. As a maintainer, I want the displayed Best derived purely from the stored best and the run's score at render time, so that the display never depends on whether the background save has completed.
7. As a maintainer, I want the write to persisted Blitz bests to keep happening on run end exactly as today, so that this fix changes only what is displayed and how "New best" is decided, not persistence behavior.

## Implementation Decisions

### End card

- The end card's Best line is computed at render from two inputs: the best currently in the Blitz bests store for this run's category, orientation, and Blitz mode, and the score of the run that just ended. The displayed value is the higher of the two; when nothing is stored yet, the displayed value is simply the run's score. This computation happens on every render, so it is correct whether or not the background write has completed by the time the card is shown.
- "New best" is decided by comparing the run's score against the best that was stored before this run ended: true when the score is higher than that prior stored best, or when there was no prior stored best and the score is above zero. The write to Blitz bests is unchanged: it continues to happen once, on run end, exactly as it does today (the same function, same trigger point). Only the display derivation and the "New best" condition change.
- No changes to the Blitz bests persistence shape, its read/write functions, or any other part of the Blitz run (setup, in-progress HUD, guesses, timers, lives).

## Testing Decisions

A good test renders the app through its public seam and asserts what a player can see: the end card's literal "Best n" text and the presence or absence of "New best" — never internal state or storage reads mid-render. It does not assert class names, CSS, animation timing, or component internals, and it does not recompute expected values the way the code does. Expected strings (`Best n`, "New best") are literals from this spec.

Test seam is fixed to the one already in use: the **App seam**. Prior art: the existing Blitz app-seam test file, which already drives a full run to completion with a memory store, memory history, and an injected UTC day, through a shared setup helper and a shared helper that commits repeated misses to end a run.

- App seam, new file (owned by this ticket): a genuine first run (no prior stored best) ends and the card reads `Best n` equal to the run's score, with "New best" shown when that score is above zero and absent when the score is zero.
- App seam, new file: a second run scoring lower than an already-stored best ends with the card still showing the higher, earlier best, and no "New best" badge.
- These tests do not duplicate or alter the existing Blitz app-seam tests, which already cover run setup, guessing, timers, and the persisted-bests write itself.

No snapshot tests, no visual regression, no Playwright. This ticket is proven done by `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm gen:schedule --check`, and `pnpm build` all passing, in addition to the App-seam coverage above.

## Out of Scope

- Everything else in Blitz: setup dialog, HUD, guessing (Default and Inverted), timers, lives, search, marks — unchanged.
- Any change to the Blitz bests persistence shape or its storage functions.
- Daily marks, shell/nav, search engine, and CI workflow work — owned by other, parallel tickets.
