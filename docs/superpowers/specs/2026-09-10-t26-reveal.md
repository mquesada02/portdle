# Spec: Reveal, stats, Share

Spec for #26. Tracker: https://github.com/mquesada02/portdle/issues/26

## Problem Statement

When a player finishes a Daily today, the answer, personal stats, and Share button appear as plain unstyled text right under the board — no visual break marks that the game just ended, nothing draws the eye to the outcome, and the page never moves to show it. The four stats and the guess histogram are bare numbers with no sense of scale. The Share button gives no confirmation that the copy worked, so a player who taps it has to trust it happened.

## Solution

Finishing a Daily — by winning or losing — draws a 1px divider across the screen, then fades in and lifts the reveal block beneath it. The reveal states the outcome ("Solved" or "The answer was"), shows the port large in monospace with a transport badge and the description, then four stats (Played, Win %, Streak, Best streak), a "Guess distribution" histogram with one bar per try scaled to the largest count and the winning try highlighted, and a full-width Share button. When the Daily finishes during the current page session, the page scrolls smoothly to the bottom 250ms after the reveal mounts; reloading an already-finished Daily shows the same reveal with no scroll. Reduced motion disables the divider draw, the reveal fade and rise, and the scroll delay and smoothing. Share keeps its existing behavior and accessible name, reading "Copied!" for 1.5 seconds after a successful copy, with the clipboard-blocked fallback text area unchanged. The engine, persistence, and routing stay exactly as they are.

## User Stories

### Reveal

1. As a player, I want the reveal to render under the board with no active row when I win or lose, so that finishing the Daily shows the outcome immediately.
2. As a player, I want a divider to draw across the screen and the reveal to fade in and rise slightly when I win or lose, so that the end of the game is marked.
3. As a player, I want the page to scroll smoothly to the reveal when I finish, so that I do not hunt for it below the board.
4. As a player who reloads a finished Daily, I want no scroll, so that the page opens where I expect.
5. As a player, I want the reveal to say "Solved" on a win and "The answer was" on a loss, so that the outcome is stated.
6. As a player, I want the port shown large in monospace with a transport badge (TCP, UDP, or TCP/UDP) and the description, so that the answer and its context are the focus.

### Stats

7. As a player, I want personal stats as four numbers, Played, Win %, Streak, Best streak, so that my stats are visible at a glance.
8. As a player, I want the histogram, headed "Guess distribution", with a bar per try count and the winning try highlighted, so that I see how today compares.

### Share

9. As a player, I want a full-width Share button that reads "Copied!" briefly after a successful copy, so that I know the share line is on the clipboard.
10. As a player whose clipboard is blocked, I want the share line shown in a selectable text area, so that I can copy it by hand.
11. As a player, I want the share line unchanged (category, date, tries, squares), so that shares from before and after the redesign look the same.

### Motion and accessibility

12. As a player with reduced motion, I want the divider draw, reveal fade and rise, and smooth scroll disabled, so that the app respects my setting.

### Maintainer

13. As a maintainer, I want the redesign to keep the existing accessible names where behavior did not change, so that the current tests keep passing with minimal edits.

## Implementation Decisions

### Design language

- The port continues to render in the system monospace stack already established for digits, ports, and the try counter; the rest of the reveal uses the system sans stack. The Share button uses the emerald color already established for correct tiles, per the palette decisions. This ticket introduces no new breakpoint or layout rule.

### Reveal

- The reveal renders in place of the current plain block, under the board, only when the Daily's status is won or lost, matching how it is already invoked today — no active row is shown alongside it (that behavior belongs to the board, unchanged here).
- A 1px divider sits above the reveal content and scales in from the center using the existing draw motion class. Below it, the outcome caption, port, badge, description, stats, histogram, and Share button sit together in a block that fades and rises into place using the existing rise motion class. Both classes and their timings (draw 300ms; rise 300ms after a 250ms delay) already exist in the global stylesheet from the shell ticket and need no changes.
- The Daily screen tracks whether the current Daily was finished during this page session (a boolean flag flipped only by a committed guess that wins or loses the game, never set on initial load) and passes it to the reveal. The reveal reads that flag to decide whether to scroll; the flag itself carries no other behavior.
- Smooth scroll to the bottom of the page fires 250ms after the reveal mounts, only when that finished-this-session flag is true. A reload of an already-finished Daily leaves the flag false and never scrolls. Under reduced motion, the scroll happens immediately with no delay and without smooth-scroll behavior; the existing reduced-motion media rule already zeroes the CSS animations, so only the scroll timing needs an explicit check of the same media query.
- The outcome caption reads "Solved" on a win and "The answer was" on a loss. The port renders large in monospace. The transport badge reads "TCP", "UDP", or "TCP/UDP" depending on the entry's transport. The description follows as prose.

### Stats

- The four stats render as a labeled stats grid: Played (count), Win % (win percentage rounded to the nearest whole number), Streak (the current streak), Best streak (the highest streak reached). "Streak" replaces the current "Current streak" label to match this spec.
- The histogram is headed "Guess distribution" and renders one bar per try count (1 through 6), each bar's width scaled to the largest count among the six and the count itself printed inside the bar. On a win, the bar for the try that won is styled distinctly (green) from the rest; on a loss, no bar is highlighted.

### Share

- Share keeps its current behavior and its accessible name "Share": on click it builds the same share line as today (unchanged format) and attempts to copy it to the clipboard. On a successful copy, the button's label reads "Copied!" for 1.5 seconds before reverting to "Share". When the clipboard is unavailable or the copy fails, the fallback read-only text area appears holding the share line, unchanged from today's behavior, and the button label does not change to "Copied!".

## Testing Decisions

A good test renders the app through its public seam and asserts what a player can see or do: roles, accessible names, and visible text. It does not assert class names, CSS, animation timing, or component internals, and it does not recompute expected values the way the code does. Expected strings are literals from this spec. The divider draw, reveal fade and rise, and highlighted-histogram-bar styling are visual details the test file does not assert.

Test seam is fixed to the one already in use: the **App seam**. Render `App` with a memory store, a memory history at a route, and an injected `utcToday`. Prior art: the existing Mixed Daily test file and the shared helpers for the memory store and `matchMedia` stub. New coverage lives in its own test file so it does not collide with the existing Mixed Daily test file. Cover:

- The reveal appears on a won Daily: the outcome caption "Solved", the port, the transport badge, the description, the four stat labels (Played, Win %, Streak, Best streak) with their values, and the "Guess distribution" heading with a count for each of the six tries.
- The reveal appears on a lost Daily: the outcome caption "The answer was", and the rest of the reveal as above.
- Clicking Share after a successful copy shows "Copied!".
- Clicking Share when the clipboard is unavailable shows the share line in a read-only text area instead of "Copied!".
- Winning or losing a Daily during the page session calls the page scroll.
- Reloading an already-finished Daily renders the reveal without calling the page scroll.
- Existing Mixed Daily behavior stays covered by its existing tests unchanged: the reveal, stats, and share assertions already in that file (port, transport badge text, description, "Played", win percentage, share text, share button) keep passing as written. None of those existing assertions check the streak label text, so the "Current streak" to "Streak" rename requires no change to that file.

No snapshot tests, no visual regression, no Playwright. This ticket is proven done by `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` all passing, in addition to the App-seam coverage above.
