# Spec: Reduced motion wins through cascade layers

Spec for #98. Tracker: https://github.com/mquesada02/portdle/issues/98. Parent: Spec 3, #87. Blocked by #92, #93, #94 (all merged); the last Spec 3 ticket.

## Problem Statement

A player who has asked their system to reduce motion still sees animation everywhere: the board's tile pop and row shake, the reveal's draw and rise, the miss popover, both dialogs, the Rounds disclosures, and every view transition all keep playing. The stylesheet's universal reduced-motion rule uses a bare `*, *::before, *::after` selector (and, for view transitions, `::view-transition-*(*)`), which has the lowest possible specificity, so every class-based keyframe rule and every type-keyed view-transition rule in the same file beats it and keeps playing. This bug predates Spec 3; ticket #91 papered over it locally for the dialogs and Rounds disclosures with a second, scoped reduced-motion rule tailored to exactly those three selectors, but the board's `.animate-*` classes and every view-transition rule Spec 3 added remained unfixed.

## Solution

Every motion rule the stylesheet writes — the four `.animate-*` classes, the popover's open and close classes, the dialog and backdrop transitions with their starting-style blocks, the Rounds disclosure rule, and every view-transition rule under every type including the root's untyped rule — moves into the `components` cascade layer, one of the four layers (`theme`, `base`, `components`, `utilities`) Tailwind 4 already declares via `@import "tailwindcss"`. The universal reduced-motion rule stays unlayered. Per the CSS Cascade Layers specification, an unlayered declaration of normal importance always beats a layered declaration of normal importance, regardless of selector specificity or source order — layer membership is compared before specificity in the cascade sort. So the universal rule now wins against every motion rule it names, present and future, without `!important` and without the per-selector scoped workaround #91 needed. #91's own scoped override is removed, since the universal rule now covers its three selectors directly.

## Implementation Decisions

### Root cause, verified in the built CSS

Before this ticket, `src/styles.css` contained `@import "tailwindcss";` followed by every motion rule the codebase writes, with no `@layer` of its own. Tailwind 4's import expands to declare four layers, in cascade-priority order: `theme`, `base`, `components`, `utilities` (Lightning CSS, Tailwind's build-time processor, also emits its own always-first `properties` layer for a `@property` fallback, unrelated to this ticket). Building the project and inspecting `dist/assets/index-*.css` confirmed that every rule `src/styles.css` wrote after the import — every keyframe, every `.animate-*` class, every view-transition rule, the dialog and backdrop rules, `details[open] > ul`, and the universal `@media (prefers-reduced-motion: reduce)` rule itself — was emitted completely unlayered, physically appended after the built `@layer utilities { ... }` block closes. With everything unlayered, ordinary specificity governed among these rules, and the universal rule's `*`-based selectors have the lowest specificity of anything in the file, so it always lost to the more specific class and type-keyed rules sharing that same unlayered bucket.

### Layer choice: `components`, not a dedicated `motion` layer

The ticket allows either the existing `components` layer or a dedicated `motion` layer declared after Tailwind's layers, conditioned on whether a Tailwind utility on an affected element would otherwise beat a motion rule once layered (`components` sits before `utilities` in Tailwind's declared order, so a utility class always beats a `components`-layer rule on the same element and property). Every element the ticket names as a risk — the How-to dialog (`src/ui/how-to.tsx`) and the setup dialog (`SetupDialog` in `src/ui/blitz-page.tsx`), the popover panel (`src/ui/miss-popover.tsx`), the disclosure lists (`LastRun` in `src/ui/blitz-page.tsx` and `BlitzRunRow` in `src/ui/history-page.tsx`), and the Codex card (`src/ui/codex-page.tsx`), plus for completeness the board and reveal (`src/ui/digit-slots.tsx`, `src/ui/daily-page.tsx`, `src/ui/daily-reveal.tsx`) — was checked for a Tailwind `opacity-*`, `scale-*`, `transition*`, or `animate-*` utility class that sets a property a motion rule also sets. None carries one. (The Daily board's tile carries an inline `style={{ animationDelay: ... }}` for its per-tile stagger; this sets only the `animation-delay` longhand, which composes harmlessly alongside whichever rule sets `animation-name`, layered or not, so it is not a conflict.) The plain `@layer components` option therefore applies everywhere; no dedicated `motion` layer is needed.

### What moves into the layer

Every existing motion-effect rule moves into `@layer components { ... }`:

- The four `.animate-*` classes (`animate-pop`, `animate-shake`, `animate-draw`, `animate-rise`).
- Every view-transition rule under every type, including the root's untyped no-animation rule: the `screen`/`phase`-shared block, the `switcher`-type block, the `reorder`-type blocks and the `screen`-type Codex-cards block from #94, and the `switcher-content` region blocks from #92.
- The popover's `.animate-popover-in` and `.animate-popover-out` classes; their `popover-in`/`popover-out` keyframes move in alongside them, since a keyframe has exactly one definition in the stylesheet and moving it causes no cross-layer keyframe conflict — the ticket permits keyframes to stay outside the layer but does not require it.
- The dialog and backdrop transition rules and their `@starting-style` blocks, and the `details[open] > ul` Rounds disclosure rule (all originally added by #91).

The five pre-existing keyframes that predate Spec 3 (`pop`, `shake`, `draw`, `rise`, `fade-out`) stay unlayered, in their original position, untouched. This means the file carries two separate `@layer components { ... }` blocks in source — one spanning from `.animate-pop` through `.animate-popover-out`, a second spanning the #91 dialog/disclosure block — with the untouched keyframes before the first and the untouched universal reduced-motion rule between them. Cascade layers with the same name merge regardless of how many times or where they are declared: building the project and inspecting the output confirmed the two source blocks merge into exactly one physical `@layer components { ... }` block, positioned between `base` and `utilities` as Tailwind's own layer order dictates, containing every motion-effect rule listed above and none of the five untouched keyframes.

Every `biome-ignore lint/correctness/noUnknownTypeSelector` comment stays immediately above the `screen`-naming selector line it covers, unchanged in content, only re-indented one level along with the rule it annotates now that it sits inside the layer block. `pnpm lint` passes with zero fixes needed, which confirms both correct formatting and that no ignore comment is left unused.

### What does not move, and one selector it gains

The universal `@media (prefers-reduced-motion: reduce) { ... }` rule stays unlayered and keeps its exact `animation`/`transition` declarations and its view-transition pseudo-element coverage. It gains one addition: `*::backdrop` is added to its `*, *::before, *::after` selector list, so the rule reads `*, *::before, *::after, *::backdrop { animation: none; transition: none; }`. This is necessary, not optional — see "Removing #91's scoped override" below for why — and it is the only edit to the universal rule's selectors; nothing about it is layered, and no `!important` is added anywhere.

### Removing #91's scoped override

#91's scoped `@media (prefers-reduced-motion: reduce) { dialog, dialog::backdrop, details[open] > ul { animation: none; transition: none; } }` rule is deleted in full, along with the comment explaining why it existed. That override existed for two distinct reasons, per #91's own spec: the universal rule's `*, *::before, *::after` selector list *does* match `dialog`, `dialog[open]`, and `details[open] > ul` — it simply *loses the cascade* to their more specific element/attribute selectors, regardless of source order, since both sides were unlayered; `::backdrop`, a pseudo-element distinct from `::before`/`::after` the way `dialog::backdrop` is distinct from `dialog`, is a case the universal rule's old selector list never matched *at all*, match or no match being a selector question layering cannot change. Layering resolves the first case cleanly: with `dialog`, `dialog[open]`, and `details[open] > ul`'s rules now in the `components` layer, the (still unlayered) universal rule wins by layer membership rather than losing on specificity. Layering does nothing for the second case, because `::backdrop` was never selected at all — no amount of winning the cascade helps a rule that doesn't match. That gap is why the universal rule's selector list itself gains `*::backdrop` (see above), mirroring how it already lists `*::before` and `*::after` as separate pseudo-element entries alongside `*` for the identical reason (confirmed against this codebase's own built CSS: Tailwind's preflight box-sizing/margin reset in `@layer base` explicitly reads `*,:after,:before,::backdrop { ... }`, listing all four as separate selectors rather than assuming `*` alone reaches any of the other three). With that addition, the universal rule genuinely reaches all three of #91's selectors, so its scoped override is fully redundant — and, left in place, stale and misleading, since the reasoning it documents (a rule "does not reach these rules") no longer matches the stylesheet.

### Cascade reasoning

Two cases confirm the fix, reasoned from the CSS Cascade Layers rule that an unlayered normal-importance declaration always beats a layered normal-importance declaration, regardless of specificity or source order:

- **Class-based case — the reveal's rise.** `.animate-rise` now sits in the `components` layer; the universal rule's `*, *::before, *::after { animation: none; ... }` stays unlayered. Under reduced motion, the unlayered rule wins on the `animation` property even though `.animate-rise`'s class selector has higher specificity, because layer membership is decided before specificity is ever compared.
- **Type-keyed case — the `screen` type's fade-out.** `:root:active-view-transition-type(screen, phase)::view-transition-old(screen) { animation: fade-out 100ms ease-out both; }` now sits in the `components` layer; the universal rule's `::view-transition-old(*) { animation: none; }` stays unlayered. Per the CSS View Transitions specification, a named pseudo-element selector such as `::view-transition-old(screen)` carries the specificity of a type selector while the `*` form carries zero specificity — yet the unlayered `*` rule still wins under reduced motion, for the same reason: layering, not specificity, decides first.

### Spec 3 amendment

`docs/superpowers/specs/2026-09-13-spec3-motion-polish.md`'s "Reduced motion and fallbacks" bullet currently opens: "The existing reduced-motion rule keeps zeroing animations and transitions." That clause is replaced with the fact that it does so only because every motion rule the stylesheet writes lives in the `components` cascade layer while the universal rule itself stays unlayered — an unlayered normal-importance rule always beats a layered one regardless of specificity. The "Stylesheet and lint" bullet gains one added sentence stating this same convention: every motion rule this spec's tickets write goes into the `components` layer, and the universal reduced-motion rule stays unlayered so it always wins against it. No other text in Spec 3 changes.

## Testing Decisions

A good test exercises a public seam with literal inputs and asserts what a player sees or what a pure function returns. This ticket is a pure CSS reorganization (moving existing rules into a cascade layer and deleting a now-redundant rule) plus a documentation edit to Spec 3; it introduces no new component behavior, state, branching, or rendered output for a test to exercise, matching Spec 3's own Testing Decisions section and #91's precedent that motion is checked by eye or by reading the built stylesheet, never by a test.

- No new test is written. Every existing test suite (App, Blitz, Blitz arena, History, Codex, Daily, Miss popover, and the rest) keeps passing unchanged: nothing in this ticket touches any `.tsx` file, component output, props, or state.
- This ticket is proven done by `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm gen:schedule --check`, and `pnpm build` all passing, plus reading the built `dist/assets/index-*.css` to confirm: exactly one `@layer components { ... }` block exists, positioned between `base` and `utilities`; it contains every motion-effect rule this ticket names and none of the five pre-existing keyframes that stay unlayered; exactly one `@media (prefers-reduced-motion: reduce)` block exists in the whole file (the universal one, now also selecting `*::backdrop`; #91's scoped override is gone, not duplicated); and `src/styles.css` itself adds no `!important` anywhere (the one `!important` in the built file is Tailwind's own pre-existing `[hidden]` preflight rule, untouched by this ticket). The class-based and type-keyed cascade reasoning above is worked through by hand against that same built output, not asserted by a test.

## Out of Scope

- Any change to any motion's timing, easing, keyframe definition, or target element — this ticket only relocates existing rules into a cascade layer, adds `*::backdrop` to the universal reduced-motion rule's selector list, and deletes #91's now-redundant override.
- `!important`, anywhere in `src/styles.css`.
- Any change to any `.tsx` file — this ticket touches `src/styles.css` and Spec 3's own spec document only.
- Any change to any other Spec 3 ticket's rules beyond moving them into the `components` layer and deleting #91's scoped reduced-motion override.
- Any new test, snapshot test, or visual regression test.
- Any change to `CONTEXT.md`: this ticket introduces no player-facing copy and no renamed concept, and reuses "Rounds disclosure" exactly as Spec 3's own Further Notes already rule it a motion name local to that spec, not a glossary term.
- Editing issue #98 or issue #87 — the coordinator syncs issue #87 after this ticket merges.
