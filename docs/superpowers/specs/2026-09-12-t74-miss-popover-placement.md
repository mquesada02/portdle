# Spec: Extract the miss popover with a placement argument

Spec for #74. Tracker: https://github.com/mquesada02/portdle/issues/74

## Problem Statement

Today `MissPopover` only knows how to sit under the Daily board's miss caption: its position, its focus-opens behavior, and its trigger element are all hard-coded for that one spot — the component always renders its own dotted-underline text button showing the entry's name. Spec 2's Codex screen will need the same panel — pin, hover, Escape, and outside-click all behaving the same way — hanging off a seen Codex card inside a grid instead of a text link inside a board row, positioned below the card, without opening just because a keyboard user tabbed past it, and with the whole card, not a text link, as the clickable trigger. Nothing about the component today lets a second caller ask for any of that.

## Solution

`MissPopover` gains a required `placement` argument, `inline` or `grid`, plus a `lastColumn` flag that only matters for `grid`. `inline` is exactly today's Daily behavior: centered under the trigger below the small breakpoint, right-edge-aligned with it above the small breakpoint, and opening on focus as well as hover, click, and pin. `grid` sits the panel below the trigger, aligned to the trigger's left edge, or to its right edge when `lastColumn` is true, at every width, and drops the focus-opens rule so tabbing past the trigger stays quiet — the panel still opens on hover, click, or Enter (which activates the button's click), and still closes on Escape or an outside click, identically to `inline`.

`MissPopover` also gains an optional `trigger` render prop: a function that receives the bundle of interaction wiring (the hover, focus, and click handlers, and the `aria-expanded`/`aria-controls` pair) and returns the element to render as the trigger, so a caller can supply its own element while `MissPopover` keeps owning all of the state above. Left unset, `trigger` defaults to today's internally-rendered dotted-underline text button showing `entry.name`, so the Daily screen passes `placement="inline"` at its one call site and needs no other change: nothing user-visible changes in this ticket. `grid` and a custom `trigger` have no production caller yet; they exist so a future Codex ticket can hang the same popover off a card with no state-model code of its own, and are proven together here by a small direct-render test rather than a Daily-screen change.

3. As a Daily player, I want the miss popover to open and stay open when I click the trigger, so that pinning it open still works exactly as it does today.
4. As a Daily player, I want Escape to close an open miss popover, so that dismissing it still works exactly as it does today.
5. As a Daily player, I want a click outside the trigger and panel to close the miss popover, so that dismissing it by clicking away still works exactly as it does today.
6. As a Daily player, I want the miss popover positioned and sized exactly as it is today (centered under the trigger on a phone, right-aligned with it on a wider screen, 16rem wide), so that this refactor is invisible on the Daily board.

## Implementation Decisions

### Miss popover

- `MissPopover` gains three props alongside the existing `entry`: `placement`, required, one of `"inline"` or `"grid"`; `lastColumn`, optional, defaulting to false, read only when `placement` is `"grid"`; and `trigger`, optional, a function that receives the interaction-wiring bundle (below) and returns the element to render as the trigger.
- State model is unchanged and shared by both placements: the three independent booleans `pinned`, `hovered`, and `focused`; the 150ms hover-grace timer between the trigger and the panel; Escape clearing all three; a pointer-down outside both the trigger and the panel clearing `pinned` and `hovered`; a click toggling `pinned`. These mechanisms are identical in both placements and don't branch on `placement`; how `focused` factors into whether the popover is open is the one exception, covered next.
- Focus-opens is that one behavioral difference: under `inline`, focusing the trigger sets `focused` and blurring it clears `focused`, exactly as today, and `focused` counts toward whether the popover is open (open whenever `pinned`, `hovered`, or `focused` is true). Under `grid`, focus is not counted toward open at all (open whenever `pinned` or `hovered` is true), so tabbing onto and off the trigger never opens or closes the panel. Hover, pin, Escape, and outside-click are identical in both placements, per Spec 2's Codex screen section: only focus-opens and position differ between `inline` and `grid`.
- The trigger element is supplied by the caller through the `trigger` render prop rather than hard-coded. `MissPopover` bundles its interaction wiring — the hover-enter/leave handlers, the focus/blur handlers, the click handler, and the `aria-expanded`/`aria-controls` pair — into one object and passes it to `trigger`, which returns whatever element the caller wants rendered; the caller spreads that bundle onto its own element. `MissPopover` keeps owning every piece of state and every rule above (pin/hover/focus, the grace timer, Escape, outside-click, and both placements' focus-opens and positioning rules) — the caller supplies only the element, never any behavior. Left unset, `trigger` defaults to a function that renders today's `<button>{entry.name}</button>`, styled as the Daily caption's dotted-underline text link, so the Daily call site needs no change beyond `placement="inline"`. A future Codex ticket supplies its own card button — whose content is the card body and whose accessible name is that visible text — as `trigger`, spreading the same bundle onto it and gaining the full state model and the `grid` placement's rules with no state-model code of its own.
- Positioning is the other behavioral difference, expressed as Tailwind classes on the panel, both keeping its existing non-positioning styling (16rem wide, rounded border, background, padding, shadow, dark-mode colors) unchanged:
  - `inline`: unchanged from today — centered under the trigger below the 640px small breakpoint, right-edge-aligned with the trigger at and above it.
  - `grid`: below the trigger at every width, left-edge-aligned with the trigger by default, or right-edge-aligned with the trigger when `lastColumn` is true. No breakpoint-dependent switch, unlike `inline`.

### Daily screen

- `daily-page.tsx`'s `RowCaption` passes `placement="inline"` at its one `<MissPopover>` call, its only change. No other part of the Daily page is touched, since ticket #73 runs in parallel on the same file.

## Testing Decisions

A good test here exercises a public seam and asserts what a player can see or do — role, accessible name, visible text, focus — never class names, CSS, or component internals, per this repo's existing testing standard. Expected strings are literals from this ticket and its parent spec.

1. **App seam** (prior art: the existing tests in `src/ui/miss-popover.test.tsx`, which already render `<App>` with a memory store, a memory history, and an injected UTC day, and drive a Daily miss to trigger the popover). Every existing test in this file keeps its existing assertions unchanged: a catalog miss with sources renders a tappable trigger closed until opened; hovering it opens the popover with name, port, description, and a source anchor; moving the pointer from the trigger into the panel keeps it open; moving off and letting the grace timer elapse closes it; clicking the trigger toggles a pinned-open state independent of hover; focusing the trigger with the keyboard opens the popover and blur closes it; Escape closes an open popover; a pointer-down outside the trigger and panel closes it; a miss that matches nothing renders plain text with no trigger and no popover.
2. **Component-level, direct render** (prior art: the same file's existing "an entry with no sources shows no sources block" test, which already renders `<MissPopover entry={...} />` directly with a fixture `CatalogEntry` rather than through `<App>`): that existing test is updated only to pass the new required `placement="inline"` prop, with its assertions unchanged. One new test of the same shape covers the `grid` placement's focus rule together with the `trigger` render prop, since neither has a production caller to exercise it through the App seam: rendering `<MissPopover>` directly with `placement="grid"` and a custom `trigger` — a button with a multi-word accessible name distinct from the fixture entry's own name, standing in for a future Codex card — asserting that focusing that custom trigger does not open the popover, that pressing Enter on the focused trigger (which activates the button, toggling the pin) opens it, and that Escape then closes it. This proves the render-prop mechanism and the `grid` focus rule together, since a future Codex ticket depends on both at once.

No visual or screenshot verification for this ticket: `grid`'s position is checked by eye once a future ticket renders it in the app, exactly as `inline`'s position is today; this ticket adds no on-screen consumer of `grid` to screenshot. No snapshot tests, no visual regression, no Playwright. This ticket is proven done by `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm gen:schedule --check`, and `pnpm build` all passing, in addition to the coverage above.

- The Codex screen, its route, its grid, its cards, and any code that renders `MissPopover` with `placement="grid"` or a custom `trigger` in the running app — this ticket only adds the `placement`/`lastColumn`/`trigger` mechanism and proves `grid` and a custom trigger together with one direct-render test, per Spec 2's Codex screen section, which is future ticket work.
- Any change to the popover's content: entry name, port, description, or sources block.
- Any change to Daily-screen behavior, layout, or content beyond the one `placement="inline"` prop at `RowCaption`'s `<MissPopover>` call — ticket #73 runs in parallel on `daily-page.tsx` and this ticket's edits there stay minimal and local to that one call site.
- Any change to Blitz, History, the catalog, the schedule, or CONTEXT.md — the glossary's Miss popover entry already reads "on a miss identification or a seen Codex card," so no glossary edit is needed here.
