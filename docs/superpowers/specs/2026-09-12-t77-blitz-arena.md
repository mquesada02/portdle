# Spec: Blitz arena and setup dialog

Spec for #77. Tracker: https://github.com/mquesada02/portdle/issues/77

## Problem Statement

A player who opens Blitz today lands on a bare setup screen: three rows of pills and a Start button, with no sense of what they played last or how their bests stack up. Nothing remembers the setup they last chose, and finishing a run drops them right back on that same blank screen with no way to see the run they just finished, or any other run, without leaving for History. The run and end-card experience (round log, "Round {n}", the full round list) already works, per ticket #72; the runs themselves are already saved and visible in History, per ticket #75. What is missing is a screen for Blitz to rest on — a place that opens on the player's last run and their bests, with setup moved out of the way into a dialog that remembers what they last picked.

## Solution

The Blitz page rests on an arena instead of the bare setup screen. Four states, one state machine: arena, dialog open over the arena, run, ended. Arena, top to bottom: the `h1` "Blitz", a "New run" button, a "Last run" section (a card summarizing the newest stored run, or "No runs yet. Start one and it will show here." when there is none), and a "Bests" section (a two-column table of every stored best, hidden entirely when none exist). "New run" opens a dialog named "New run" holding the same three setup groups as today — Category and Mode stay pills, Orientation becomes two captioned radio cards, per the prototype's variant B — preselecting the last run's setup, or Mixed/Default/Sprint on a first visit. Escape, a backdrop click, or "Cancel" close the dialog for free; "Start" begins a run exactly as today. Play again returns to the arena, not to the dialog, so the player sees the run they just finished before deciding whether to go again. The run screen and the end card are unchanged beyond what ticket #72 already shipped — no setup badges on the end card, since the setup just played is not in question.

## User Stories

Renumbered sequentially for this ticket, following the convention prior per-ticket specs (t72, t74, t75) already set; each story traces back to Spec 2 (`docs/superpowers/specs/2026-09-11-spec2-blitz-history-codex.md`).

### Blitz arena

1. As a player, I want the Blitz screen to open on an arena instead of the setup screen, so that I see what I did last and what my bests are before I decide to play.
2. As a player, I want one "New run" button at the top of the arena, so that starting a run is a single obvious tap.
3. As a player, I want a "Last run" block showing the setup, why it ended and when, and the score, so that I can pick up where I left off.
4. As a player, I want to expand the last run's round log from the arena, so that I can reread what I missed without replaying.
5. As a player with no runs yet, I want the arena to say "No runs yet. Start one and it will show here.", so that an empty arena still tells me what to do.
6. As a player, I want a "Bests" table with one row per category, orientation, and mode I have scored in, so that my bests are visible without starting a run.
7. As a player with no bests yet, I want the Bests section hidden, so that the arena is not a table of dashes.
8. As a player, I want "Play again" on the end card to return me to the arena with the run I just finished as the last run, so that I see the updated arena before deciding to go again.

### Setup dialog

9. As a player, I want "New run" to open a dialog named "New run" with the Daily category, Orientation, and Mode groups, so that setup does not take over the page.
10. As a player, I want the dialog to preselect the setup of my last run, so that replaying my usual setup is two taps.
11. As a first-time player, I want the dialog to preselect Mixed, Default, and Sprint, so that the first run needs no decisions.
12. As a player, I want each Orientation option to show its title and a one-line caption, "Default" / "See a service, type its port." and "Inverted" / "See a port, pick the service.", so that I understand the choice without leaving the dialog.
13. As a player, I want Escape, a backdrop click, or a Cancel button to close the dialog without starting a run, so that opening it costs nothing.
14. As a player, I want the "Cannot start Blitz: not enough unused answers today." notice to show inside the dialog when the pool is empty, so that the failure is next to the Start button that caused it.
15. As a keyboard player, I want the dialog to trap focus and return focus to "New run" when it closes, so that it behaves like the How-to dialog.

### Maintainer

16. As a maintainer, I want the storage seam to stay synchronous and storage-agnostic, so that this spec's record shapes carry over unchanged when a later backend replaces the adapter and makes the seam async. (No storage shape changes in this ticket; the arena and dialog only read `blitzRuns` and `blitzBests` through the existing seam.)

## Implementation Decisions

### Shared badge module

- A new module, `src/ui/blitz-badges.tsx`, is the one place `ORIENTATION_LABEL` and `MODE_LABEL` (duration-stripped: "Sprint", "Marathon", "Survival" — not "Sprint (1m)") live, plus a `SetupBadges` component that renders the category, orientation, and mode pill badges for a setup, reusing the existing `CATEGORY_LABEL` from `src/engine/share.ts`. It also holds `localDate` and `localTime`, the two small formatters that turn a run's `endedAt` instant into the viewer's local `YYYY-MM-DD` and `HH:MM` — both the arena's "Last run" card and History's Blitz segment need them from the same instant, and Spec 2 requires both surfaces to render dates and times the same way.
- `src/ui/history-page.tsx`'s local `ORIENTATION_LABEL`, `MODE_LABEL`, `BlitzBadge`, `localDate`, and `localTime` are replaced by imports from this new module. This is a pure extraction: `BlitzRunRow`'s three separate `<BlitzBadge>` calls become one `<SetupBadges category={run.category} orientation={run.orientation} mode={run.mode} />`, and the two date helpers keep their exact existing behavior. No visible or test-visible change to History's Blitz segment.
- The dialog's own Category and Mode pills keep their existing, separate, duration-bearing labels ("Sprint (1m)", etc.) defined locally in `blitz-page.tsx` as today — `blitz-badges.tsx`'s duration-stripped labels are for read-only badges only, never for the dialog's own inputs, per Spec 2's explicit carve-out.

### Blitz screen: arena

- `BlitzPage`'s state machine gains one new piece of state, `dialogOpen: boolean`, defaulting to `false` — the dialog never auto-opens. The existing `category`/`orientation`/`mode` state's initial values are now derived once, at mount, from `persist.readBlitzRuns()[0]` when a run exists (that run's category, orientation, and mode), falling back to `mixed`/`default`/`sprint` when it does not. This state is not reset each time the dialog opens or closes; it simply starts pointed at the last run's setup.
- The arena replaces today's bare setup screen (the current `!run` branch) top to bottom:
  - The `h1` "Blitz" and `ProgressNotice`, unchanged in position.
  - A "New run" primary button that sets `dialogOpen` to `true`. This is the only way the dialog opens.
  - A "Last run" section, headed by an `h2` "Last run": when `persist.readBlitzRuns()` is non-empty, its first element (newest, since `prependRun` always keeps the list newest-first) renders as a card: `SetupBadges` for the run's setup; "Time's up" or "Out of lives" per the run's `ended` reason, followed by the local date and time of `endedAt` as `YYYY-MM-DD HH:MM` (composed from `blitz-badges.tsx`'s `localDate` and `localTime`); the score, reusing the existing "Score {n}" copy (per ticket #75's own precedent of reusing that string outside the HUD); and a native `<details>`/`<summary>` disclosure titled "Rounds ({n})" containing the run's `rounds` rendered by the existing `RoundLog` component, in play order (the array is already oldest-first, so no reversal is needed — unlike the in-run three-line log, which slices and reverses). When there are no stored runs, the section instead shows the text "No runs yet. Start one and it will show here." with no card.
  - A "Bests" section, headed by an `h2` "Bests", rendered only when `persist.readBlitzBests()` has at least one entry (the whole section, heading included, is absent otherwise). A two-column table with no header row: one row per stored best, `SetupBadges` in the first cell, "Score {n}" in the second, ordered by category (`mixed`, `protocols`, `applications`, matching the existing `DAILY_CATEGORIES` order), then orientation (`default`, `inverted`), then mode (`sprint`, `marathon`, `survival`, matching the existing `MODES` pill order). This ordering is a plain sort over `Object.entries(persist.readBlitzBests())`, parsing each `${category}|${orientation}|${mode}` key; it is presentation logic local to `blitz-page.tsx`, not an engine function, since nothing in Spec 2's Testing Decisions asks for an engine-seam test of it.

### Blitz screen: setup dialog

- A new `SetupDialog` piece, rendered only from the arena branch, using the exact dialog mechanics `src/ui/how-to.tsx` already established: a `dialogRef`, a `useEffect` that calls `showModal()` when `open` becomes true and `close()` when it becomes false, a document-level `keydown` listener for `Escape` while open, and a click handler on the `<dialog>` element itself that closes when `event.target` is the dialog (the backdrop), not its inner content. All three dismiss paths — Escape, backdrop click, and the new "Cancel" button — call one `closeDialog` function that sets `dialogOpen` to `false` and clears the empty-pool error; none of them write anything to storage. The `<dialog>`'s `aria-labelledby` points at a visible `h2` reading "New run", giving the dialog its accessible name. The native `<dialog>` renders as a top layer over the arena rather than replacing it in the DOM, so the arena's `h1` "Blitz" and its `ProgressNotice` stay exactly where they are, underneath, while the dialog is open — the notice's placement is unaffected by `dialogOpen`.
- Category and Mode keep their existing `fieldset`s, legends, radio group names (`blitz-category`, `blitz-mode`), and `Pill` rendering, unchanged from today's setup screen.
- Orientation stops being two `Pill`s and becomes two radio "cards" (from the prototype's variant B), sharing the group name `blitz-orientation`. Each card's `<label>` wraps only the radio input and the visible title ("Default" or "Inverted"), so the accessible name computed from that label stays just the title. Each card's caption ("See a service, type its port." / "See a port, pick the service.") is a sibling element outside that `<label>`, wired to the radio via `aria-describedby` — visually part of the same card, but structurally outside the name-bearing label, so it becomes the radio's accessible description instead of joining its name. This is the resolution to the prototype's own finding: a floating callout under an info icon covered the Inverted pill inside a 343px-wide dialog; the two-card layout with inline captions does not.
- Below the three groups: "Start" (the existing primary-button styling and the existing `start()` logic — unchanged except that a successful start now also sets `dialogOpen` to `false`, closing the dialog as the run begins), then the empty-pool notice (the existing `poolError` state and its unchanged copy, "Cannot start Blitz: not enough unused answers today.", rendered only when non-empty), then "Cancel" (calls `closeDialog`) — in that order: Spec 2 describes a "Start" primary button followed by a "Cancel" text button, with the empty-pool notice rendering between them.
- The run screen and the end card (the `run` and `ended` branches of `BlitzPage`, and `submitGuess`, `submitInverted`, `applyResult`, `playAgain`, and the run-end `useEffect` that already writes `blitzRuns`/`blitzBests`) are untouched by this ticket. `playAgain` already resets `run` to `null`, which is precisely what makes the arena the screen Play again lands on — no new logic is needed there. Ticket #73 runs in parallel and edits the guess-handling code this ticket does not touch, so this ticket's diff in `blitz-page.tsx` stays confined to the `!run` branch and the new top-level `dialogOpen` state and initial setup values.

### Copy

Strings this ticket introduces or reuses, all fixed by Spec 2 or by existing Blitz/History copy: "New run", "Last run", "Bests", "No runs yet. Start one and it will show here.", the Orientation captions "See a service, type its port." and "See a port, pick the service." (their titles reuse the existing radio labels "Default" and "Inverted"), "Cancel", the existing "Start" copy (unchanged, now inside the dialog), the existing "Rounds ({n})" heading and round-log copy (unchanged, reused from ticket #72's `RoundLog`), the existing badge forms "Sprint", "Marathon", and "Survival" (the first two duration-stripped, from `blitz-badges.tsx`; "Survival" already has none), the existing category labels "Mixed", "Protocols", and "Applications" (from `CATEGORY_LABEL`, reused by `SetupBadges` in every Last-run card and Bests row), the existing "Score {n}" copy (reused for the arena's Last run score and each Bests row's score, per ticket #75's precedent), and the existing "Time's up", "Out of lives", and "Cannot start Blitz: not enough unused answers today." copy, all unchanged. No new strings beyond what Spec 2's own Copy section already fixes.

## Testing Decisions

A good test exercises a public seam with literal inputs and asserts what a player sees or does — role, accessible name, visible text — never class names, CSS, or component internals. Expected strings are literals from Spec 2 and this ticket.

Test seam is fixed to the one already in use: the **App seam**. Render `App` with a memory store, a memory history, and an injected `utcToday`. Prior art: `src/ui/blitz.test.tsx`, `blitz-best.test.tsx`, `blitz-runs.test.tsx`, and `history-page.test.tsx`; the shared `memoryStore`/`stubMatchMedia`/`portDigits` helpers in `src/test/helpers.ts`; Blitz tests derive the current entry from the `h1` heading, as today; the page receives no rng, only the reducer does, so nothing new needs injecting.

1. **New file, `src/ui/blitz-arena.test.tsx`** (kept separate from `blitz.test.tsx`, mirroring the precedent `blitz-runs.test.tsx` and `blitz-best.test.tsx` already set, so this ticket's tests do not collide with ticket #73's parallel edits to `blitz.test.tsx` and the guess-handling parts of `blitz-page.tsx`):
   - Arena, empty: with no stored runs and no stored bests, the page shows "No runs yet. Start one and it will show here." and no "Bests" heading.
   - Arena, bests only: with a stored best and no stored runs, the empty-state line and the "Bests" heading show together.
   - Arena, seeded: with one stored run and its matching best, "Last run" shows the run's score and a mode badge reading "Sprint" (never "Sprint (1m)"), and opening the "Rounds ({n})" disclosure reveals the seeded round lines; "Bests" lists one row whose mode badge reads "Sprint" the same way.
   - Arena, Bests ordering: with bests stored for Protocols/Default/Sprint and Mixed/Inverted/Survival, the Mixed row renders before the Protocols row.
   - Arena, save failure: using a store whose `setItem` always throws, with `howToSeen` pre-seeded directly into the store's underlying map (bypassing the write path, so the How-to dialog's own dismiss-and-save does not also fail and trip Shell's separate, differently-placed notice) — the run-end write already sets the page's existing `saveWarning` state on a failing store, and `playAgain` does not clear it, so finishing a run and clicking "Play again" leaves the "Progress may not save." notice (`role="status"`) showing once back on the arena, asserted within the arena's `<main>` so it is unambiguously the arena's own notice and not Shell's. This is the same failing-store-plus-`role="status"` assertion technique `app.test.tsx`'s "failed write shows the shared Progress notice" test already uses, though that test's own trigger (a failed `writeHowToSeen`) and placement (Shell-level, above every page) are different — only the technique is shared, not the scenario.
   - Dialog, open and preselect: clicking "New run" opens a dialog named "New run"; with a seeded run, its setup's radios are the ones checked; with no run, Mixed, Default, and Sprint are checked.
   - Dialog, dismissal: Escape, a click on the dialog's backdrop, and a click on "Cancel" each close the dialog and return focus to "New run" (asserted via `document.activeElement`, the same general technique `mixed-daily.test.tsx` and `miss-popover.test.tsx` already use for focus assertions; the restore-to-"New run" behavior specifically relies on the `showModal`/`close` focus-capture polyfill already in `src/test/setup.ts`, exercised the same way `mixed-daily.test.tsx`'s How-to-close assertions already do — `miss-popover.test.tsx`'s own focus checks exercise plain DOM focus, not that polyfill, and are cited only for the shared assertion style).
   - Dialog, Orientation captions: both captions are visible text inside the dialog, and each radio's `aria-describedby` points at an element whose text is that radio's caption.
   - Dialog, Start: clicking "Start" (with the dialog's default preselection) closes the dialog and begins a run whose HUD reads "Round 1".
   - End card, Play again: finishing a run and clicking "Play again" lands back on the arena, where "Last run" shows the score of the run that was just finished.
2. **Existing files, mechanical updates for the new flow** — every place that starts a run must first open the dialog:
   - `src/ui/blitz.test.tsx`: each of its existing tests that clicks "Start" (directly, or after first clicking a setup radio) first clicks "New run" to open the dialog; every other assertion in those tests is unchanged. Two tests additionally have their post-arena assertion changed from a visible "Start" button to a visible "New run" button, since Start now lives inside a dialog that is closed once the player returns to the arena: the "play again returns to setup" test and the "refresh during a run returns to setup" test (both renamed if the surrounding assertion text no longer matches "setup", kept otherwise). The one test that asserts the setup fields directly, with no prior click ("setup shows Blitz heading category orientation mode and Start"), is deleted from this file — none of the elements it checks (the radios, the Start button) exist on the arena before "New run" is clicked, so its coverage is superseded outright by the new file's "Dialog, open and preselect" test, which checks the same preselected radios and the Start button inside the opened dialog.
   - `src/ui/blitz-best.test.tsx`: its three tests each gain a "New run" click before their existing "Start" click; no other change.
   - `src/ui/blitz-runs.test.tsx`: its two tests each gain a "New run" click before their existing "Start" click; no other change.
   - `src/ui/history-page.test.tsx`: no change. It seeds runs directly through `persist.writeBlitzRuns`, never through the UI's Start flow, and its assertions read visible text/roles that the badge-extraction refactor does not alter.

No snapshot tests, no visual regression, no Playwright. This ticket is proven done by `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm gen:schedule --check`, and `pnpm build` all passing, in addition to the seam coverage above, plus the phone- and desktop-width screenshots called for in the work assignment (checked by eye, not asserted in a test, per this repo's existing convention for layout and placement).
