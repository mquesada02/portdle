# Spec: History

Spec for #4. Tracker: https://github.com/mquesada02/portdle/issues/14

## Problem Statement

A player can play today's three Dailies, but `/history` is still a placeholder heading. They cannot see past Daily answers (date, category, name, port). Today's unplayed answers must stay hidden, and future tail ids must never leak. History is not a place to play old days.

## Solution

`/history` is a read-only list of scheduled Daily answers. Every scheduled Daily whose date is before today is listed for all three Daily categories. Today's row for a Daily category appears only after that category is `won` or `lost` in this browser. Future tail ids are never listed. Newest date first. Rows show date, category, name, and port. There are no play links. Players cannot open or replay those days from History.

## User Stories

1. As a player, I want to open `/history` and see a heading History, so that I know I am on the History surface.
2. As a player, I want History to be a read-only list of past Daily answers, so that I can look up what already shipped without playing it again.
3. As a player, I want each row to show the UTC date, Daily category, canonical name, and port, so that I can identify that day's answer.
4. As a player, I want the list newest first, so that the most recent answers are at the top.
5. As a player looking at one UTC date that has three scheduled Dailies, I want Mixed, then Protocols, then Applications on that date, so that the three categories have a stable order.
6. As a player, I want every scheduled Daily with a date before today listed, so that the archive of already-dealt days is complete.
7. As a player who never opened yesterday's Mixed, I still want yesterday's Mixed name and port in History, so that History is answers, not only days I played.
8. As a player who left yesterday's Protocols in `playing`, I still want yesterday's Protocols answer in History, so that an unfinished past day is not hidden.
9. As a player who has not finished today's Mixed, I want today's Mixed row absent, so that History does not spoil today's Mixed.
10. As a player who has not finished today's Protocols, I want today's Protocols row absent, so that History does not spoil today's Protocols.
11. As a player who has not finished today's Applications, I want today's Applications row absent, so that History does not spoil today's Applications.
12. As a player who won today's Mixed in this browser, I want today's Mixed row listed, so that a finished Mixed is visible the same day.
13. As a player who lost today's Protocols in this browser, I want today's Protocols row listed, so that a lost Daily is still History.
14. As a player who won Mixed today but has not finished Protocols, I want today's Mixed row and not today's Protocols row, so that finish is per Daily category.
15. As a player whose today's Mixed persist is `playing`, I want today's Mixed row absent, so that an in-progress board is not treated as finished.
16. As a player whose today's Mixed persist JSON is corrupt, I want today's Mixed row absent, so that a bad key does not spoil Mixed.
17. As a player, I want future tail ids never listed, so that the future tail stays secret.
18. As a player whose persist somehow has a future Daily key, I still want that future date absent from History, so that persist cannot leak the tail.
19. As a player on epoch day who has finished nothing, I want History to have no rows, so that there is no past yet and today is unspoiled.
20. As a player on epoch day who finished Mixed only, I want exactly today's Mixed row, so that the other two Dailies stay hidden.
21. As a player, I want days before the schedule epoch never listed, so that there is no Daily before the first public day.
22. As a player, I want a scheduled id that is missing from that Daily category's catalog skipped, so that a broken slot does not render a blank answer.
23. As a player, I want rows not to be play links, so that I cannot open those days from History.
24. As a player, I want no extra play control on History, so that History does not invite archive play.
25. As a player, I want History not to deep-link a row to `/`, `/protocols`, or `/applications` for that date, so that clicking a row cannot start or resume a Daily.
26. As a player, I still want the shell nav Mixed · Protocols · Applications · Blitz · History · Help, so that chrome is unchanged.
27. As a player, I want the canonical `name` on a row, never an alias, so that History titles match Daily titles.
28. As a player, I want the port shown as the decimal integer with no leading zeros (80, not 080), so that the answer matches how the port is stored.
29. As a player, I want Daily category labels Mixed, Protocols, and Applications, so that History uses the same English labels as nav and Share.
30. As a player, I want dates shown as `YYYY-MM-DD` UTC calendar dates, so that History days match persist keys and Share dates.
31. As a first-time player who lands on History, I still want the How-to dialog, so that teaching is not lost.
32. As a player who dismissed How-to, I want History without the dialog, so that returning visits are not blocked.
33. As a keyboard-only player, I want to reach History from the nav without a pointer, so that the surface is reachable.
34. As a player, I want one `h1` on History (the word History), so that heading structure stays one per screen.
35. As a player, I want English copy only, so that v1 stays one locale.
36. As a player, I want Blitz to stay a stub with heading Blitz, so that this ticket does not ship Blitz.
37. As a player, I want Mixed, Protocols, and Applications Daily play unchanged, so that History does not alter guess, persist, or streaks.
38. As a player, I want Help, theme, and How-to copy unchanged, so that chrome stays as already shipped.
39. As a player whose tab is on History after UTC midnight, I want History to use the injected/current `utcToday`, so that yesterday becomes past and today's unfinished rows hide.
40. As a player, I want History to list all three Daily categories' past schedules, so that Mixed, Protocols, and Applications answers sit in one list.
41. As a player looking at two past dates, I want the later date's three rows above the earlier date's three rows, so that newest-first is by date, not by category.
42. As a player, I want a frozen-prefix Daily whose entry was later retired still listed with that id's catalog `name` and `port`, so that a later retirement does not erase History.
43. As a maintainer, I want History rows computed by a pure engine function with injected `utcToday`, schedules, catalogs, and `finishedToday`, so that tests do not use the clock or `localStorage`.
44. As a maintainer, I want the engine to stay free of React, DOM, and `localStorage`, so that History listing is unit-testable.
45. As a player, I want no cookies, analytics, accounts, or network besides static assets, so that History stays a local static SPA surface.

## Implementation Decisions

- **Seams** (already implied by the v1 design spec §6.4 / §9.5; no new seam): (1) **engine** — pure `historyRows`; no React, no DOM, no `localStorage`; (2) **UI** — `/history` through `App`; Vitest + Testing Library. Persist is the existing adapter: the UI reads `readDaily(category, utcToday)` and maps `status === "won" || status === "lost"` to `finishedToday`. Do not add persist keys. Tests inject `utcToday`, schedules, catalogs, and `finishedToday` (engine) or persist (UI). The browser UI passes `utcToday` from the existing router context and loads the production JSON catalogs plus the three committed schedules.

- Closed unions unchanged: `CatalogKind = "protocol" | "application"`; `DailyCategory = "mixed" | "protocols" | "applications"`. Do not add Orientation, BlitzMode, inverted guess, search, or a Blitz reducer. Do not add archive play, skip, or History persist.

- Engine (pure):

  ```ts
  type HistoryRow = {
    date: string;
    category: DailyCategory;
    name: string;
    port: number;
  };

  historyRows({
    utcToday,
    schedules,
    protocols,
    applications,
    finishedToday,
  }): HistoryRow[]
  ```

  `finishedToday` is `Record<DailyCategory, boolean>`. The engine does not read persist.

  Include a scheduled Daily when `date < utcToday`, or when `date === utcToday` and `finishedToday[category]` is true. Never include `date > utcToday`. Resolve each slot with existing `getDaily(category, date, schedule, protocols, applications)`. Skip a slot when `getDaily` returns null (uncovered day, day before epoch, or unknown id). Name and port come from that catalog entry (frozen-prefix identity already forbids changing them for past + today).

  Sort: date descending (`YYYY-MM-DD` lexicographic order is chronological). Same date: Mixed, then Protocols, then Applications (`DAILY_CATEGORIES` order).

  Walk every cycle in each schedule; do not assume a single cycle. Days before epoch are not assigned (`getDaily` null) and are not listed.

- UI: replace the History placeholder with a History screen. One `h1` `History`. A list whose accessible name is that heading (`aria-labelledby` the `h1`; do not invent extra list copy). Each item shows date (`YYYY-MM-DD`), category label (`Mixed` / `Protocols` / `Applications` — same map as Share), canonical `name`, and `port` as the decimal integer with no leading zeros. Items are not links (`a` / router `Link`). No play CTA, no date route, no “Play” control. Empty list is allowed (heading + empty list, no extra empty-state copy). How-to on first visit is unchanged. Shell nav is unchanged. Blitz stays `PlaceholderPage` heading Blitz.

- UI derives `finishedToday` only from today's persist: `readDaily(category, utcToday)?.status` is `won` or `lost`. Missing, corrupt, or `playing` → false. Future persist keys are ignored.

- Do not change Daily screens, guess, stats, Share, catalogs, schedules, `gen:schedule`, Help, theme, or How-to copy. Nav Mixed / Protocols / Applications remain the way to play today; they are shell, not History rows.

- No Playwright, no GitHub Actions this ticket. No cookies, analytics, accounts, or network besides static assets.

## Testing Decisions

A good test checks observable behavior through a public interface. It does not inspect private helpers, mock internal collaborators, or recompute the expected value the way the production code does. Expected values are literals from this spec (heading `History`, labels `Mixed` / `Protocols` / `Applications`, dates `YYYY-MM-DD`, ports without leading zeros, `finishedToday` booleans).

Two seams (same as Implementation Decisions):

1. **Engine** — `historyRows`. Tiny injected catalogs and schedules, injected `utcToday`. Cover: yesterday listed when `utcToday` is the day after a scheduled day; today absent when all `finishedToday` are false; today's Mixed row present when `finishedToday.mixed` is true and the other two today rows absent; future tail ids never appear; a date after the last scheduled day lists only past scheduled days; unknown id skipped; day before epoch skipped; same date ordered Mixed then Protocols then Applications; later date's rows before earlier date's rows; two cycles both contribute past days; `playing` is a UI concern (engine only sees the boolean). Do not use wall-clock. Do not test Blitz, guess, or `gen:schedule`.

2. **UI** — Vitest + Testing Library + jsdom through `App`. Inject persist, memory history, `utcToday`. Resolve past answers with `getDaily` against production JSON + committed schedules (same helper as Daily tests). Cover: `/history` `h1` is History; with `utcToday` after epoch and no today finishes, every scheduled day before today appears (newest first) and today's date is absent; after writing Mixed `won` (or `lost`) for `utcToday`, Mixed's today date/name/port appear and unfinished categories' today rows do not; `playing` Mixed today does not list Mixed today; corrupt Mixed persist for `utcToday` does not list Mixed today; no row's date is after `utcToday`; the History list contains no links; How-to still appears on a first History visit; Blitz heading stays Blitz. Do not assert CSS class names except existing `html.dark` shell tests. Do not drive Blitz gameplay. Do not add Playwright.

Prior art: engine tests next to sources; Mixed / three-Dailies UI tests through `App`. Follow those.

Typecheck and the full Vitest suite pass.

## Out of Scope

- Archive play, replay of a past Daily, skip, inverted Daily
- Blitz (default or inverted), search index, Blitz reducer
- Accounts, leaderboards, PWA, i18n, custom domain, IANA scrape
- GitHub Actions / GitHub Pages deploy
- Changing How-to copy, theme rules, or nav labels
- Changing catalogs, schedules, `gen:schedule`, guess, stats, or Share
- Extra empty-state marketing copy
- Cookies, analytics, backend, UI kit, Redux/Zustand
- New persist keys (`blitzBests` still out)
