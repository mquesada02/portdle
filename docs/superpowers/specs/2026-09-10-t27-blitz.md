# Spec: Blitz screens

Spec for #27. Tracker: https://github.com/mquesada02/portdle/issues/27

## Problem Statement

A player who opens Blitz today sees three rows of bare radio buttons for Daily category, Orientation, and Mode, with no sense of which option is selected beyond reading each radio. Starting a run shows plain, unstyled lines for lives, score, and the countdown, so none of the run state reads at a glance. The empty-pool error is plain text under Start. In Default orientation an invalid or duplicate guess is silent — it shows a message but the digit slots never shake, unlike the Daily's board. In Inverted orientation the Search panel shows "No matches." even before the player has typed anything, and its highlighted row is not visually distinct. When a run ends, the end card states the score and the stored best but gives no sign of whether this run's score is a new personal best. The run logic and timing already work; the player just cannot read a run's state or its outcome at a glance.

## Solution

Blitz setup keeps its three existing `fieldset` groups (Daily category, Orientation, Mode) and their radio accessible names, but renders each option as a pill: visually hidden radios, pill-styled labels, the checked pill filled and the rest outlined. Start becomes a large primary button, and the empty-pool error becomes a styled inline notice under it. Once a run starts, a HUD row shows three heart icons carrying one accessible label "Lives: n" (a spent life renders as an outlined heart), the score, and — in every mode but Survival — the remaining time as `m:ss` in monospace. The prompt (the service name in Default, the port in Inverted) renders as the centered `h1`, with the Inverted blurb beneath it when the current port is crowded. Default keeps using the Daily's shared digit-slot control, now wired the same way the Daily wires it: an invalid or duplicate guess shakes the row and keeps the digits, driven by Blitz's own existing message copy. Inverted keeps its combobox named "Service name" with its Search panel inline beneath it: up to 20 name-only rows, scrollable once they exceed the panel's height, the highlighted row visibly marked, and "No matches." shown only once the player has typed a non-empty query — the panel shows nothing before that. Miss messages keep their existing copy, styled as the inline message under the input. When a run ends, the end card keeps the `h1` "Blitz" and shows why the run ended ("Time's up" or "Out of lives"), the score large, the stored best ("Best n" or "Best —"), a "New best" badge when this run's score beat the best that was already stored before this run's finish was recorded, and a "Play again" button that returns to setup. Engine, persistence, routing, and game rules do not change.

## User Stories

### Setup

1. As a player, I want Blitz setup with three pill groups for category, orientation, and mode and a large Start button, so that starting a run is three taps.
2. As a player, I want the selected pill filled and the others outlined, so that the current choice is obvious.
3. As a keyboard player, I want the pills to remain native radio groups underneath, so that arrow keys move within a group.
4. As a player, I want the empty-pool error styled as an inline notice under Start, so that the reason is readable.

### HUD

5. As a player, I want a HUD row during a run with three hearts for lives, the score, and a `m:ss` countdown, so that the run state is one glance.
6. As a player in Survival, I want no countdown shown, so that the HUD does not promise a timer that does not exist.
7. As a player, I want a spent life shown as an empty heart, so that losing a life is visible.

### Run screen

8. As a player, I want the prompt (service name in Default, port in Inverted) large and centered, so that the entry being asked about is the focus.
9. As a player in Inverted on a crowded port, I want the blurb under the port, so that the hint is where I look.
10. As a player in Default, I want the same digit slots as the Daily, so that both modes feel the same.
11. As a player in Default, I want an invalid or duplicate guess to shake the row and keep my digits, so that the rejection feels the same as it does on the Daily.
12. As a player in Inverted, I want the search input and the Search panel inline below it, so that the list never fights the phone keyboard.
13. As a player in Inverted, I want results to show names only, so that ports are never leaked in the list.
14. As a player in Inverted, I want the highlighted row visible and Enter or click to pick it, so that keyboard and pointer both work.
15. As a player in Inverted, I want "No matches." only after I have typed something, so that the empty box does not nag.
16. As a player, I want the miss message ("{name} is {port}", "Wrong service, same port.", or the identified name) inline under the input, so that I learn without a modal.

### End card

17. As a player, I want an end card with "Time's up" or "Out of lives", the score large, the stored best, and a "New best" mark when I beat it, so that the run ends with a result.
18. As a player, I want a Play again button on the end card that returns to setup, so that the loop is one tap.
19. As a player, I want the Blitz heading to stay "Blitz" on setup and end screens, so that the surface stays named.

### Maintainer

20. As a maintainer, I want the redesign to keep the existing accessible names where behavior did not change, so that the current tests keep passing with minimal edits.
21. As a maintainer, I want the Blitz test file updated for the pills, HUD, Search panel, and end card while every existing Blitz behavior test stays green, so that the redesign does not regress Blitz.
22. As a maintainer, I want the shared digit-slot control reused with no changes to its contract, so that Default and the Daily stay in sync without duplicated logic.
23. As a maintainer, I want the engine, persistence, and routing untouched, so that this ticket stays a pure UI restyle.

## Implementation Decisions

### Design language

- Blitz follows the shell and Daily's established zinc palette for surfaces and text, and the same monospace-for-digits-ports-and-timers, sans-for-everything-else split. No web fonts, no UI kit, no state library.
- Every new element this ticket introduces — the pills, the HUD hearts, the empty-pool notice, and the end card's New best badge — defines both light and dark colors, continuing the existing `dark` class on `html`.

### Setup

- The three existing `fieldset` groups and their radio accessible names are unchanged. Each radio input becomes visually hidden; its associated label renders as a pill, filled when checked and outlined otherwise.
- Start becomes a large primary button. The empty-pool error keeps its existing copy and becomes a styled inline notice under Start.

### HUD

- The HUD is one row: three heart icons wrapped by a single element carrying the accessible name "Lives: n" (the icons themselves are presentational); remaining lives render as filled hearts, spent lives as outlined hearts. The score keeps its existing copy. The remaining time renders as minutes and zero-padded seconds (`m:ss`, e.g. `1:00`, `0:45`) in monospace, computed from the existing per-second countdown. Survival renders no time element at all, not merely a hidden one.

### Run screen

- Default keeps using the shared digit-slot control exactly as the Daily wires it: an invalid or duplicate guess triggers the control's shake key and leaves the digits in place, using Blitz's own existing message copy — the same shared message functions and the same shake-and-keep-digits mechanism the Daily uses, not identical message text for every guess outcome. Per the precedent already set in the Daily board ticket (#24), the "Not enough digits." versus "Not a valid port." split belongs to the Daily screen only and was deliberately kept out of the message set shared with Blitz, so Blitz's message set gains no new strings.
- Inverted's Search panel gets a fixed height that shows six rows before scrolling, so results beyond that height scroll rather than growing the page. The highlighted row is visibly marked beyond `aria-selected`. The panel's "No matches." text is gated on the query being non-empty: with an empty query the panel renders nothing, matching the parent spec's requirement — this is a behavior change from the code as it stands today, where "No matches." also shows before the player types.
- The prompt and, in Inverted, the blurb keep their current source of truth — the existing crowded-port determination already driving whether a blurb appears; this ticket only changes how they render, not when they appear.

### End card

- The end card keeps its existing copy for the outcome line, the score, and "Best n" / "Best —". A "New best" badge is shown only when this run's final score is strictly greater than the best that was stored for that category, orientation, and Blitz mode combination immediately before this run's finish was recorded — the comparison uses the best as it stood before the run's write, not the value the run's own write may have just produced. Play again keeps its existing behavior and accessible name.

## Testing Decisions

A good test renders the app through its public seam and asserts what a player can see or do: roles, accessible names, visible text, focus, and persisted keys through the injected store. It does not assert class names, CSS, animation timing, or component internals, and it does not recompute expected values the way the code does. Expected strings are literals from this spec.

Test seam is fixed to the one already in use: the **App seam**. Render `App` with a memory store, a memory history at the Blitz route, and an injected `utcToday`. Prior art: the existing Blitz test file, plus the shared helpers for the memory store and the `matchMedia` stub, and the existing helper for reading the digit slots (already shared with the Daily's tests). Cover:

- Setup: the three pill groups remain radios with their existing accessible names, all focusable; the checked radio for each group reflects the current selection; Start is present and focusable.
- HUD: starting a run shows the accessible name "Lives: 3", the existing score copy, and `1:00` for Sprint; Survival shows no time text at all; after a life is spent the accessible name reads "Lives: 2".
- Default run: typing an invalid guess still shows Blitz's existing message copy; a correct or catalog-miss guess still updates score, lives, and the heading as today.
- Inverted run: the combobox keeps its name "Service name"; an empty query shows no "No matches." text and no options; a non-empty query with no hits shows "No matches."; a listed option can be picked by click or Enter, keeping today's miss-message and life-spend behavior.
- End card: ending a run still shows "Time's up" or "Out of lives", the existing score and best copy, and Play again returning to setup; a run whose score exceeds a previously stored best shows a "New best" mark, and a run that does not beat a previously stored best shows no such mark.
- Every other existing Blitz behavior test (starting a run, scoring, spending lives, ending by timeout or lives, writing and preserving bests, refresh returning to setup, inverted crowded/unique heading text) stays green, with assertions updated only where this spec's decisions change how state is exposed: lives move from visible "Lives n" text to the accessible name "Lives: n"; the countdown moves from raw-seconds text to `m:ss`; the empty-query "No matches." assertion is removed since that text no longer appears before typing.

No snapshot tests, no visual regression, no Playwright. This ticket is proven done by `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` all passing, in addition to the App-seam coverage above.

## Out of Scope

- The Daily screen, the Daily reveal, and their test file — separate tickets own that surface
- The catalog `sources` schema, catalog validation, and catalog JSON
- Any change to the shared digit-slot control's props, behavior, or visuals beyond reusing it as it stands
- Any change to the miss-message copy itself
- The miss popover in Blitz (it stays Daily-only, per the parent spec)
- A stats modal, an on-screen keypad, separate desktop and phone designs
- Any new game feature, rule change, engine change, persistence key, or route
- Stabilizing the existing Blitz test that spends a life using real `Math.random()`

## Further Notes

- Primary source: `docs/superpowers/specs/2026-09-10-ui-redesign.md` (issue #22), sections Design language and Blitz, plus that spec's Testing Decisions Blitz bullet. This ticket also follows the Daily board ticket's (#24) decision that Blitz's own message set does not gain a "Not enough digits." case, per the Run screen decision above. Prototype reference: branch `prototype/ui`, commit `fd70684` — illustrative only, never merged.
- Glossary: `CONTEXT.md` at the repo root defines Blitz, Orientation, Blitz mode, Life, Best, HUD, Search panel, End card. Use those words in tests and code; avoid "speed run"/"practice"/"arcade" for Blitz, "direction"/"skill" for Orientation, "try"/"heart (the icon, not the concept)" for Life, "high score"/"record" for Best, "status bar"/"scoreboard" for HUD, "dropdown"/"autocomplete"/"suggestions" for Search panel, and "results screen"/"game over"/"summary" for End card.
- Product and architecture authority remains the v1 design spec and the UI redesign spec; this ticket is one slice of that spec's Blitz decisions. The hearts' single grouped accessible name "Lives: n" is not this ticket's own call — the parent spec's Further Notes already settles it ("hearts carry the accessible label 'Lives: n' with spent lives outlined").
- Author calls not covered by the parent spec or the ticket body, listed so they can be overruled: the "New best" comparison uses the best as it stood immediately before this run's finish, not any value the run's own write may have already produced; the Search panel's fixed height shows six rows before scrolling; the pre-existing flaky Blitz test that spends a life using real `Math.random()` is left exactly as is. The empty-pool notice is implemented per its Implementation Decision but is not covered by an App-seam test: the seam renders through the real production catalogs, which have far more answer-eligible entries per category than the three a day can exclude, so the empty-pool path cannot be triggered without a way to inject a smaller catalog, which is out of scope. The parent spec's own Testing Decisions Blitz bullet does not require this coverage either. Similarly, a "duplicate" guess is implemented per the shared message copy and shake behavior but is not covered by a test in Default orientation: `reduceBlitz` (the pure, unchanged engine reducer) always evaluates a Blitz guess against an empty prior-guess list, so the engine can never produce a duplicate outcome for Blitz regardless of what the player types — duplicate detection is a Daily-only engine behavior, out of scope to change here.
