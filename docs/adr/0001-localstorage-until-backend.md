# localStorage until a backend

Portdle stores all player state in localStorage behind one synchronous storage seam. While specifying Spec 2 (Blitz runs, round log, Codex) we considered moving game data to IndexedDB now, and Firebase for cross-device sync, because a real database and API are planned. We chose to stay on localStorage: the data is small (about 1 MB at the caps, against a 5 MB localStorage budget), IndexedDB would force an async seam and a test fake for no player-visible gain, and a later backend brings its own client cache, so moving to IndexedDB first would mean two migrations instead of one. New records are plain JSON reachable only through the seam (the Codex keyed by entry id, runs identified by their end instant), so the backend effort imports them mechanically. That effort is its own spec; it decides the service, makes the seam async, and imports localStorage once.
