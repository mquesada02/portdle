# localStorage stays the local store

Amends [ADR 0001](0001-localstorage-until-backend.md). While specifying the backend ([Spec 4](../superpowers/specs/2026-09-28-spec4-backend.md): accounts, sync, and leaderboards) we chose Supabase, which ships no offline client cache. So localStorage stays the local store and every screen keeps reading it; sync layers on top of it and exchanges changes with the account. The storage seam (`Persist` over a `KeyValueStore`) stays synchronous and every existing read and write stays where it is. `Persist` gains only what sync needs: the sync bookkeeping keys (including the id of the account the device last synced with), listing the dates that have a stored Daily for a category, and clearing every Portdle key; `KeyValueStore` and `memoryStore` gain key removal and key listing for that. There is no second migration. This supersedes two ADR 0001 statements: "a later backend brings its own client cache" and "makes the seam async". Its "imports localStorage once" stands, as the first sign-in import.
